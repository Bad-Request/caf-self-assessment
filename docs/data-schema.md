# CAF dataset schema — `assets/data.json`

`assets/data.json` is the source of truth for the NCSC Cyber Assessment
Framework (CAF) reference content shown in the app. The browser fetches it
directly (`assets/js/model.js`); bump `CACHE_VERSION` in `sw.js` after
editing it so offline installs pick up the change.

## Shape

```
Objective[]
```

### Objective

| Field | Type | Notes |
|---|---|---|
| `id` | string | Single letter: `"A"`, `"B"`, `"C"`, `"D"`. |
| `title` | string | e.g. `"Managing security risk"`. |
| `description` | string | The objective's summary paragraph from the CAF document. |
| `principles` | `Principle[]` | |

### Principle

| Field | Type | Notes |
|---|---|---|
| `id` | string | e.g. `"A1"`, `"B4"`. |
| `title` | string | e.g. `"Governance"`. |
| `description` | string | The principle's summary paragraph. |
| `outcomes` | `Outcome[]` | The principle's contributing outcomes. |
| `ncscUrl` | string | Link to the principle's page on ncsc.gov.uk. |
| `guidance` | `Guidance` (optional) | Further reading for the principle, from NCSC's [Consolidated view of CAF Guidance](https://www.ncsc.gov.uk/collection/cyber-assessment-framework/consolidated-view-of-caf-guidance). Generated by `tools/extract_ncsc_guidance.js` — don't hand-edit. |

### Guidance

| Field | Type | Notes |
|---|---|---|
| `ncsc` | `GuidanceItem[]` (optional) | The page's "NCSC Guidance" list. Omitted if empty. |
| `external` | `GuidanceItem[]` (optional) | The page's "External resources" list. Omitted if empty. |

### GuidanceItem

One list entry, in one of three shapes:

| Shape | Meaning |
|---|---|
| `{ "title" }` | Plain text, no link — e.g. standards listed by name only (`"ISO/IEC 27001"`). Never invent a URL for these. |
| `{ "title", "url" }` | The whole entry is a single link. |
| `{ "title", "links": [{ "text", "url" }] }` | A sentence with one or more links inside it. Each `text` appears in `title`, in order. |

`title` is the entry's full text as worded on the NCSC page (whitespace
normalised). Every `url` is absolute.

### Outcome (a "contributing outcome", e.g. `B4.a`)

| Field | Type | Notes |
|---|---|---|
| `id` | string | e.g. `"B4.a"`. |
| `title` | string | e.g. `"Secure by Design"`. |
| `description` | string | The outcome's "You ..." summary sentence(s). |
| `type` | `2 \| 3` | `2` = two-column table (Not Achieved / Achieved only). `3` = three-column table (Not Achieved / Partially Achieved / Achieved). Determines whether `partial` is present. |
| `not` | `string[]` | Indicators of Good Practice (IGPs) for **Not Achieved**. In the PDF this column is headed "At least one of the following statements is true" — any one of these being true means the outcome is not achieved. |
| `partial` | `string[]` | IGPs for **Partially Achieved**. Only present when `type` is `3`. Headed "All the following statements are true" in the PDF. |
| `achieved` | `string[]` | IGPs for **Achieved**. Headed "All the following statements are true" in the PDF. |

Each IGP string is one bullet/statement, exactly as worded in the CAF PDF,
with whitespace normalised to single spaces and line-wrap hyphenation
rejoined. Do not paraphrase or summarise IGP text — the app relies on the
official wording.

## Invariants a reviewer should check before committing an update

- Every outcome's `not`/`partial`/`achieved` arrays contain **only** bullets
  that belong to that column in the source PDF for that specific outcome —
  the most common defect (see `tools/extract-caf-pdf.py`'s validation
  report) is a bullet bleeding into the neighbouring column, usually because
  the PDF table's row heights differ between columns.
- No outcome should have `partial` and `achieved` arrays containing the same
  set of bullets — this indicates a botched split (both columns still hold
  everything, unsplit).
- No IGP bullet should be an exact duplicate of another bullet in the *same*
  column of the *same* outcome (bullets legitimately repeat verbatim across
  a `partial`→`achieved` pair sometimes — e.g. "Generic, shared, default
  name and built-in accounts have been removed or disabled..." can appear
  in both `partial` and `achieved` for the same outcome in the official
  document — but never twice within one column).
- `type: 2` outcomes must not have a `partial` key at all (omit it, don't
  set `[]`).
- Counts are a useful smoke test but not proof of correctness — always spot
  check wording against the PDF for any outcome the tool flags.

# Plain-English summaries — `assets/plain-english.json`

Optional, **unofficial** one-sentence summaries of individual IGPs, shown
under the official wording when the user turns on the "Plain English"
preference (never printed). They are our own wording, not NCSC's, and are
kept in a separate file from `data.json` so that the official dataset stays
verbatim and `tools/extract_caf_pdf.py` can regenerate `data.json` without
touching them. It's in `sw.js`'s `APP_SHELL`, so bump `CACHE_VERSION` after
editing it. If the file is missing or fails to load the app still works,
just without summaries.

## Shape

```
{ "<outcome id>": { "not"?: Entry[], "partial"?: Entry[], "achieved"?: Entry[] } }
```

Each array is aligned by index with the same outcome's column in
`data.json` — entry `i` summarises IGP `i`. Outcomes, columns, or trailing
entries without a summary are simply omitted (a `null` entry can hold a
gap mid-array).

### Entry

| Field | Type | Notes |
|---|---|---|
| `src` | string | Fingerprint (32-bit FNV-1a of the UTF-8 text, 8 hex digits — `fingerprint()` in `assets/js/utils.js`) of the exact official IGP wording this summary was written for. |
| `text` | string | The summary itself. |

The app only shows a summary whose `src` matches the current official
text, so when NCSC revise an IGP its old summary disappears instead of
sitting next to wording it no longer describes. Fix it by re-reading the
new IGP and rewriting `text`, then updating `src` — never update `src`
alone.

## Writing summaries

- One sentence, 20 words or fewer, British English, second person ("You…").
- Keep the polarity: a Not achieved summary must still read as a failing.
- Keep the qualifiers that change the meaning: "all" vs "some",
  "regularly", "board", and especially **"common threats"** (usually the
  Partially achieved bar) vs **"capable and well-resourced threat
  actors"** (usually the Achieved bar).
- An IGP repeated verbatim in `partial` and `achieved` gets the same
  summary in both.
- Don't add advice, examples or requirements that aren't in the IGP.

## Checking

```
node tools/check_plain_english.mjs           # validate + coverage per objective
node tools/check_plain_english.mjs stub B2.a # skeleton entries with src filled in
```

The check fails on unknown outcomes/columns, out-of-range entries, stale
`src` fingerprints and empty summaries, and warns about summaries over 20
words.
